# 4. Authentication Header (AH)

## Definition
AH is IP protocol 51 and provides connectionless integrity, data-origin authentication, and optional anti-replay protection.

## Purpose
AH can authenticate selected portions of an IP packet without providing confidentiality.

## How it works
AH inserts an authentication header containing a Security Parameters Index (SPI), sequence number, and integrity check value. Mutable fields are treated according to AH processing rules.

## Important components
Next Header; Payload Length; SPI; Sequence Number; Integrity Check Value; SA.

## Configuration concepts
AH can be used in transport or tunnel mode, but it is uncommon in modern VPNs because NAT changes fields that AH authenticates and ESP can normally provide the needed services.

## Important parameters
Authentication/integrity algorithm, SA, SPI, anti-replay window, mode, traffic selectors.

## Example
EXAMPLE CONFIGURATION: A lab-only host-to-host policy could select AH transport mode for a controlled experiment. Prefer ESP for normal VPN deployments.

## Common mistakes
Expecting AH to encrypt data; allowing AH through a firewall as TCP/UDP; assuming AH is NAT-friendly.

## Troubleshooting
Verify IP protocol 51 reachability, SA state, algorithm match, SPI state, and whether NAT is altering authenticated header information.

## Security considerations
AH does not provide confidentiality and is generally less interoperable with NAT. Use ESP unless AH is required by a specific, justified design.

## Related concepts
ESP, integrity, data-origin authentication, transport mode, tunnel mode, NAT-T.

## FAQ
**Does AH encrypt?** No.
**What is AH's IP protocol number?** 51.
